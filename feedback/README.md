# 서울대학교 미술대학 80주년 · 궤적 그리기

첨부된 Figma SVG와 프로토타입 영상을 바탕으로 구현한 모바일 중심 정적 웹사이트입니다. 패키지 설치나 빌드가 필요 없습니다.

## 실행

```sh
cd /workspace/80th-Anniversary
python3 -m http.server 8002 --bind 0.0.0.0 --directory /workspace/80th-Anniversary
```

브라우저로 정적 서버에 접속합니다. 배포는 기존 Vercel의 정적 사이트 구성을 사용할 수 있습니다. 촬영·공유·클립보드는 실제 휴대폰의 HTTPS 사이트에서 확인합니다.

## 로그인 없는 공개 피드백 배포

공유 주소: https://yeonjoo-kim.github.io/80th-Anniversary/feedback/

테스트한 수정본을 커밋한 다음 실행합니다.

```sh
python3 scripts/publish_feedback.py --publish
```

이 스크립트는 현재 체크아웃을 바꾸지 않고 `codex/public-feedback` 브랜치에 정적 스냅샷을 만듭니다. 기존 GitHub Pages 루트 파일은 `main`에서 그대로 복사하고 `/feedback/` 아래에 수정본을 둡니다. Pages의 배포 원본만 이 브랜치로 설정하며 `main`과 Vercel 운영 사이트에 쓰지 않습니다. 후속 피드백 배포 때도 최신 main 루트 파일을 보존합니다. `--publish` 없이 실행하면 계획만 출력합니다.

연결 계정에 Pages 설정 권한이 없어 HTTP 403이 반환되면 스냅샷 업로드까지 완료하고 종료 코드 2와 설정 안내를 출력합니다. 이 경우 저장소 **Settings → Pages → Build and deployment**에서 **Deploy from a branch → codex/public-feedback → /(root) → Save**를 한 번 선택합니다. 배포 원본이 선택되기 전에는 위 주소가 활성화되지 않습니다.

생성된 GitHub Actions 작업은 인증·쿠키 없는 실제 HTTPS 요청으로 공개 주소의 HTML·JS·CSS·오디오를 읽고 커밋된 파일 해시 및 오디오 MIME을 확인합니다. Pages 빌드와 이 확인의 성공 여부를 확인한 후 링크를 공유합니다. Supabase의 익명 로그인은 작품을 저장할 때만 쓰며, 방문자가 사이트나 아카이브를 여는 데 로그인 화면은 없습니다.

## 화면과 기능

- 랜덤 컬러 랜딩을 터치 → 8색 컬러 홈 → 사진 촬영/선택 → 그리기 애니메이션 → 완성 결과. 랜딩 화살표는 기존보다 3배 느린 3.6초의 가속 낙하로 표시하며 착지 후 튕기지 않습니다. 5차 첨부 SVG의 다섯 경로와 겹침 순서를 그대로 사용합니다. SVG 비율을 유지하고 화면 비율에 맞춰 보여주는 범위를 조정합니다. 모바일은 원본 프레임을 포함하고 PC는 화살표 몸통까지 표시합니다.
- 홈 컬러 패턴은 2초마다 바뀌며 좌우로 움직여도 순환합니다. 버튼은 호버·탭·누른 채 움직이기에 팔레트의 다른 색으로 반응하며 INFO는 색상 효과를 제외합니다. 미술대학·조형연구소·80주년 로고는 해당 사이트로 연결하며, 10-10 Project는 로고만 표시합니다. 아카이브 버튼은 오른쪽에서 7번째(왼쪽 두 번째) 칸에, 가져오기→촬영하기와 같은 간격으로 촬영하기 아래에 놓았습니다.
- 사진은 원래 비율을 유지하며 표시하고, 긴 세로 사진은 전체가 화면에 들어오도록 축소합니다. 모바일에서는 그리기 버튼이 사진 아래 일정 간격을 유지하고 배경 화살표 하나가 천천히 떠다닙니다. 1024px 이상 PC에서는 버튼이 오른쪽 상단에 있고, 화살표 세 개가 화면 전체를 14·17·20초 주기로 이동합니다. 모바일 배경은 16초로 느리게 이동합니다. 사진과 Fin의 PNG 프레임은 화면 가로 중앙에 두고, 상단을 뒤로가기와 같은 여백으로 맞춥니다. 아카이브를 제외한 모바일 화면은 스크롤 없이 표시합니다.
- 랜딩 글자는 상단 14px·한글 제목 24px·영문 제목 27px, Home 제목은 30px로 조금 키웠습니다. PC 랜딩은 상단 16px·한글 제목 27px·영문 제목 30px이고 로고는 중앙에 배치합니다. PC의 Home 세로 버튼은 마우스 입력 환경에서도 28px보다 작아지지 않으므로 창 너비가 1024px 아래로 내려가도 모바일 크기로 떨어지지 않습니다. 다른 PC 본문·버튼은 화면에 맞춰 조정하고, Home 로고는 왼쪽 하단에 정렬됩니다. Info 본문 폭은 최대 1280px이며 넓은 화면에서는 한글/영문을 두 열로 배치합니다. Info 한글 자간은 -0.03em입니다. PC 본문은 최소 18px를 유지하고 공간이 부족하면 본문 영역 안에서 스크롤합니다. 사진의 그리기 버튼과 완성 화면의 세 버튼은 같은 오른쪽 상단 위치·크기이며, 완성 버튼은 세로로 쌓입니다. 아카이브 뒤로가기는 Info·Photo와 같은 왼쪽 상단으로 통일합니다. 제목은 PC에서 Home과 같은 30px, 모바일 터치 환경에서는 26px이며 Back 오른쪽에 같은 행으로 배치합니다.
- Info와 Photo 등의 뒤로가기 버튼은 4차 수정의 화살표를 1초마다 다른 모양·팔레트 색으로 표시합니다. 결과·사진/Info 배경·뒤로가기는 `assets/arrows/`의 동일한 원본 경로를 사용합니다. 제공된 7개는 변경하지 않고, 누락된 Arrow 3은 사용자 선택에 따라 Arrow 4를 위아래 반전합니다. 랜딩은 5차 첨부 SVG의 고정 구도이고, Processing은 4차 수정 직전의 막대·패턴 프레임 8장으로 복원했습니다. `prepare_arrows.py`는 Processing 자산을 생성하지 않습니다.
- Info의 행사명은 `A decade Recorded, A decade Envisioned`, 마지막 문장은 `This website was created by Yeonjoo Kim, Jung Ah Lee, and Chris Hamamoto.`와 이에 맞춘 한글 번역입니다. 한글·영문 양끝정렬, 자동/선택적 하이픈, 한글 1.8·영문 1.65 행간을 사용합니다. 작은 화면에서는 전체 내용이 보이도록 글자 크기를 조정합니다.
- 사진의 색 면적과 위치·선 구조를 분석해 8방향의 화살표 조합을 만듭니다. 색 면적 기준은 3%이며 검출이 약하면 가장 많이 검출된 색 하나, 검출색이 없는 흰색·검정색이면 기본 파랑을 사용합니다. 중간 밝기의 회색도 8색 중 하나로 분석합니다.
- 궤적+한국 시간 생성 날짜 이미지와 사진·벡터 포스터 글자가 합쳐진 이미지를 각각 정확한 4:5 비율의 1200×1500px PNG로 만듭니다. 타이포 SVG 전체의 실제 외곽 중심을 계산해 포스터 프레임 중앙에 배치하며, 사진은 하단 첫 기관 로고의 시작선에 맞춘 별도 레이어이며 로고 위 간격은 8 SVG 단위입니다. 날짜는 Panchi Mono 18px로 줄이고 오른쪽 위로 옮겨 하단 행사 정보와 간격을 확보했습니다. 변경은 새 결과에 적용하며 기존 저장 이미지는 보존합니다.
- 완성 화면은 궤적과 포스터를 800ms마다 번갈아 보여주며 **다운로드 / 다시하기 / 궤적 아카이브**를 같은 크기의 3개 버튼으로 제공하며 Fin의 INFO는 제거했습니다. 다운로드 메뉴에는 **궤적 저장하기 / 포스터 저장하기 / 둘 다 저장하기 / 궤적 아카이브**가 있습니다. 둘 다 저장은 지원되는 휴대폰에서 두 PNG를 하나의 공유 메뉴로 전달하고, 그 외에는 두 파일의 다운로드를 요청합니다. 취소하면 메뉴에 남으며 완료 후 아카이브로 이동합니다.
- 공개 아카이브는 세로 4:5 카드의 최신순 스크롤 목록입니다. 12건씩 추가로 읽고 중복 ID는 표시하지 않습니다. 기본은 궤적+날짜이며 호버·누르고 있기로 원본 사진을 4:5 안에 채워 보여줍니다. 카드를 짧게 누르면 사진과 궤적을 나란히 보는 `#result/{UUID}` 상세로 이동하며, 돌아오면 목록과 스크롤 위치를 유지합니다. 상세의 세로 사진은 화면에서만 4:5로 자르고 가로 사진은 전체 비율을 유지합니다. 원본 저장 파일은 수정하지 않습니다. 이전/다음 이동에는 각각 Arrow 4와 Arrow 1을 고정해 표시하고 날짜 설명·이미지 캡션·저장 버튼을 제거했습니다. 목록과 상세의 배경은 8색 팔레트의 불투명 단색 중 무작위로 선택합니다. 사진은 처음 상호작용할 때 불러옵니다.
- 사진(긴 변 최대 2400px JPEG), 궤적 PNG, 포스터 PNG를 IndexedDB에 자동 보관합니다. 온라인 미연결 상태는 같은 브라우저에서만 다시 볼 수 있습니다.
- Supabase 설정 후에는 세 파일을 Storage에 자동 업로드하고 데이터베이스에 결과 정보를 저장합니다. 온라인 저장 완료 후에는 다른 기기에서도 결과 링크를 열 수 있습니다.
- 첨부 MP3의 타격음 8구간은 활성 버튼의 클릭·탭·Enter/Space 실행에만 한 번 재생합니다. 호버·포커스 이동·배경 탭·드래그·링크·스크롤·자동 처리 전환은 무음입니다. 지원 기기에서는 버튼 실행에 진동을 호출합니다. 별도의 소리/진동 토글은 없습니다. OS의 동작 줄이기에서는 자동 애니메이션·교대를 멈춥니다. iOS Safari는 웹 진동을 지원하지 않습니다.

## 폰트와 기기 제약

- 영문 기본은 자체 호스팅한 **Playfair Display 500 Italic**이며, 랜딩 상단의 영문과 Info 본문은 **500 정체**입니다. INFO 버튼은 **Pretendard Regular(400)**입니다. 생성 이미지 날짜는 제공받은 **Panchi Mono**를 로드한 Canvas에 그려 PNG에도 반영합니다.
- 한글은 사용자 요청으로 제공받은 **KoPubWorld 바탕**으로 우선 대체했습니다. 모든 한글 제목·본문·안내·버튼은 **Medium(500)**입니다. 파일은 WOFF2로 변환해 자체 호스팅하며, 열린명조 연결 정보 없이도 방문자에게 같은 글꼴을 제공합니다.
- 가져오기는 클릭 동작 안에서 기본 사진 선택창을 즉시 엽니다. 사이트 중간 메뉴나 비동기 파일 시스템 선택 단계를 두지 않습니다. iOS Safari의 기본 ‘사진 보관함/사진 찍기/파일 선택’ 메뉴는 사이트 코드로 강제 생략할 수 없습니다.
- 소리의 기본 재생은 아이폰을 포함해 Web Audio 버퍼를 사용합니다. 터치/클릭 동작 안에서 AudioContext를 활성화하고 중단 상태를 재개합니다. 아이폰에서는 별도의 무음 AAC 루프를 사용자 동작에서 시작해 미디어 재생 세션을 유지합니다. 이 무음 요소의 재생을 효과음 청취 검증으로 간주하지 않습니다. 실제 효과음은 정규화된 PCM 버퍼의 8구간이고, 약 100ms 뒤 HTML 플레이어를 강제로 정지하던 방식은 제거했습니다. Web Audio가 없는 경우에만 0.35초의 무음 꼬리가 붙은 AAC 조각을 자연 종료까지 재생합니다. 실제 iPhone Safari에서 들리는지는 기기 확인이 필요합니다.
- Home은 콘텐츠의 안전 영역 여백과 분리된 고정 배경을 사용합니다. 수직 패턴을 노치 위·하단 안전 영역과 큰 뷰포트(100lvh)까지 확장하고 문서 루트 및 테마 색도 갱신합니다. Safari 자체의 주소창·도구 모음은 웹페이지 바깥의 UI입니다.
- 첨부 파비콘 SVG를 사용하며, 같은 도형을 렌더링한 PNG와 iOS 홈 화면 아이콘도 제공합니다.

## Supabase 연결

[설정 안내](SUPABASE_SETUP.md)에 따라 익명 로그인과 두 SQL을 설정합니다. 기존 프로젝트는 `setup.sql`과 공개 아카이브용 `archive.sql`까지 적용됐으며 실제 게스트 조회를 확인했습니다. 이번 디자인 수정에는 추가 SQL 실행이 필요 없습니다. 사용자 제공 공개 URL과 Publishable Key는 `supabase-config.js`에 적용되어 있습니다. 서비스 계정이나 비공개 키는 사용하지 않습니다.

## 파일

- `index.html`, `styles.css`: 화면, 모바일 레이아웃과 접근성 구조.
- `app.js`: 사진 입력, 화면 이동, 피드백, PNG 생성, 저장 UI.
- `core.js`: 사진 분석과 색·방향 계산.
- `archive.js`: IndexedDB와 Supabase REST 저장 어댑터.
- `assets/`: 제공된 SVG에서 분리한 글자·로고·화살표·처리 프레임. 예시 사진과 예시 날짜는 포함하지 않습니다.
- `supabase-config.js`, `supabase/setup.sql`, `supabase/archive.sql`: 공개 연결 설정, 테이블·이미지 버킷·접근 정책, 공개 아카이브 조회 함수.
- `tests/`: 실제 브라우저의 로컬 생성·다운로드·기록 복구 및 색상 분석 검증.
- `scripts/prepare_arrows.py`, `scripts/prepare_audio.py`: 원본 SVG에서 공용 자산 생성, 원본 녹음의 PCM 추출·정규화 및 AAC 대체 파일 생성. 오디오 재생성에만 ffmpeg가 필요하며 앱 배포에는 준비된 파일을 사용합니다.

## 검증

```sh
node --test tests/core.test.cjs
python3 tests/smoke.py http://127.0.0.1:8002
python3 tests/design_browser.py
python3 tests/revision7_browser.py http://127.0.0.1:8002
python3 tests/archive_browser.py http://127.0.0.1:8002
```

Python 브라우저 테스트는 Playwright와 `/usr/bin/chromium`을 사용합니다. 로컬 테스트는 공개 Supabase 설정을 테스트 안에서 비활성화하고, 10가지 화면 크기·이미지 생성·실제 폰트 로드·타이머·아카이브 hover/hold/tap·기존 IndexedDB 보존을 확인합니다. 진동과 오디오 호출 검사는 실제 기기의 촉각·청취를 대신하지 않습니다. REST 테스트는 요청을 모의 처리하여 업로드 실패·재시도·세 파일 완료 후 결과 행 저장·로그인 없는 아카이브/결과 조회를 검사하며 실제 서비스 검증과 구분합니다.

SQL 문법과 접근 정책도 독립 PostgreSQL 환경에서 검증할 수 있습니다. 앱 실행에는 아래 테스트 의존성이 필요하지 않습니다.

```sh
npm install --prefix /tmp/80th-sql-tests --package-lock=false --no-audit --no-fund @electric-sql/pglite@0.3.14
NODE_PATH=/tmp/80th-sql-tests/node_modules node --test tests/sql_policies.cjs
```

이 검증은 이 앱의 SQL과 소유자/방문자 권한을 확인하며, 실제 Supabase Storage 서비스의 파일 검증이나 콘솔 적용 여부는 별도로 확인해야 합니다.

실제 Supabase 저장과 새 브라우저 조회·다운로드 검증 결과 및 테스트 자료 정리 방법은 [VERIFICATION.md](VERIFICATION.md)에 기록했습니다. 운영 사이트에는 아직 배포하지 않았습니다.

## 현재 레이아웃과 전체 화면 실행

랜딩은 원본 SVG 다섯 경로와 겹침 순서를 유지하며 가로·세로에 같은 배율을 적용합니다. 모바일과 PC 모두 원본 402×874 프레임의 중심·세로 범위·배율을 유지하고, 넓은 화면에서는 좌우로 더 보이는 만큼 몸통이 드러나도록 viewBox를 조정합니다. 배경은 화면 전체를 채우고 제목 크기는 이전 지정값을 유지합니다.

새 포스터의 사진 왼쪽은 타이포 중앙 정렬 후 하단 첫 기관 로고의 시작선과 일치하며 로고 위에 8 SVG 단위의 간격을 둡니다. 기존 저장 이미지에는 소급 적용하지 않습니다. 아카이브 목록·상세는 제목(PC 30px·모바일 26px) 왼쪽에 Back을 나란히 두며 링크 복사는 제거했습니다.

Fin·그리기·다운로드 창의 색상 버튼은 최초 Fin.svg의 사각형(201×85, rx 20) 비율을 유지합니다. 화면에 따라 크기를 바꾸되 너비와 높이가 서로 다른 비율로 늘어나지 않습니다. 다운로드 창은 네 버튼과 상태 문구를 화면 높이 안에 수용하도록 전체 너비를 조절합니다.
